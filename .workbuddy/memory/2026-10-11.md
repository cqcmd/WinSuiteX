## 硬件页滚动到底「网卡」组被裁 + 截图长图裁尾 · 同一根因修复

**症状**（Z.W. 真机截图，v0.1.9）：硬件页滚动条拉到底后底部「网卡」分组显示不完整；「截图」导出的长图同样裁尾。

**根因**：`draw_hw_page` 量高趟与绘制趟**值列宽度不一致**。
- 量高趟（pages.rs ~934）：所有行一律按全宽 `lay.max_w()` 用 `wrap_value` 算折行行数；
- 绘制趟（~978-987）：带健康徽标的行把值列右界收窄 `DISK_BADGE_RESERVE(=64)` 再折行；
- 真机硬盘 4 行全带「健康」徽标、3 行值串长到全宽 1 行/收窄 2 行 → 总高量矮（每行少算 `ROW_H=22`）→ `max_scroll()` 偏小 → 拉到底最后一组被 footer 盖住；
- 截图 `capture_hw_page` 的长图高度与裁剪高都取 `draw_hw_page` 返回值 → 量矮多少裁掉多少。**一个修复解决两个症状**。

**修复**：量高趟按行复刻绘制趟的收窄——`s.health.get(i)` 有徽标时用 `lay.max_w() - scale(DISK_BADGE_RESERVE)`，否则全宽。

**回归测试**（smoke_tests::hw_measure_height_accounts_badge_narrowed_wrapping）：
- 新增 `#[cfg(test)] pages::hw_value_widths(w)` 暴露 `(全宽, 收窄宽)` 口径（测试取真源几何，不重抄）；
- 测试把盘型号逐字符加长，直到**真实 build_hw_sections 产出的硬盘行值**满足「全宽行数 < 收窄行数」（现场 wrap_value 判定，字体/DPI 变化不脆），再比较有/无徽标两形态的 `draw_hw_page` 返回总高，断言带徽标版严格更高；
- **回退验证**：临时把量高趟改回全宽（`if false`）→ 测试红；还原 → 绿。测试确实罩得住本 bug。

**教训（防复发）**：`kv` 折行宽度属于"量高/绘制双趟共用几何"，任何一侧单独改（如再给某类行加右侧预留：网卡速率、温度色等）都会重演此类漂移。新增行级预留时必须同步改量高趟，并优先考虑把行数计算收敛成"wrap 一次、两趟共用"。

## 提权（UAC）议题：Z.W. 定「先不做」（结论备查，勿再重复提议）

**问题**：运行时能否自动提权管理员运行？
**结论：不能静默自动提权**——这是 UAC 安全边界（标准令牌进程无法自我提权）。静默提权即 UAC 绕过（计划任务/COM/注入），属恶意软件行为，杀软必报，**明确不做**。所需弹窗无法省掉（除非 UAC 被整体关闭，那种情况本来就是完整令牌，无需提权）。

**现状盘点（已查证）**
- `app.rc` 清单 `asInvoker`（有意不弹 UAC）；
- 采集层已有 `physical_disk.rs::process_is_elevated()`（`GetTokenInformation(TokenElevation)`）→ `ctx.set_admin_elevated()` → `CollectResult.info.admin_elevated`；
- 报告（lib.rs:105）与 CLI（main.rs:322）**已用**该字段显示未提权提示（报告是红色警告横幅）；
- **GUI 面板完全没用这个字段** —— 面板不知道自己未提权，SMART 采不到只显示「未读取（可能需管理员）」，看不出原因。这是将来若要做的第一个落点。

**三方案与 Z.W. 决定**
- A 清单改 `requireAdministrator`：每次双击弹 UAC；标准用户账户输不了密码就**打不开程序**，网吧批量部署烦。
- B 一键提权重启（`ShellExecuteW` "runas"）+ 面板提示（我推荐）。
- C 仅面板提示，不加按钮。
→ **Z.W. 选：先不做**（维持现状；报告里已有红色警告横幅）。

**若将来做 B，四个坑（备查）**
1. ⚠️ **单实例 mutex 会吞掉提权重启**：新进程启动时老进程未退 → 命中「切前台后自己退出」→ 点了没反应。必须给提权进程传 `--elevated` 标记跳过激活逻辑（main.rs:354/374-399）。
2. 工作目录会变（可能落 System32）→ `ShellExecuteW` 必须显式传 `lpDirectory`，否则报告存错位置（按 exe 同目录存）。
3. UAC 被取消返回 `SE_ERR_ACCESSDENIED(5)` → 不能退出当前进程，要留在原界面。
4. 标准用户账户弹的是"输管理员凭据"，受限账户/无密码机器走不通 → 文案需说明。

**产品判断**：多数硬件信息（CPU/内存/主板/显卡/网卡/分区）**不需要管理员**，仅 SMART 深度数据与右键菜单写注册表需要。故默认 asInvoker 双击即跑是合理的，提权属按需增强而非必需。

## frameless 窗口与任务栏的两个契约（第三十一轮，重要）

Z.W. 真机反馈「任务栏没图标 + 单击任务栏不最小化/恢复」。两者都是 **frameless 的代价**，且都不会崩、无日志——只能靠行为断言兜住。新增 `tools/check_window_behavior.py`。

**① 任务栏/Alt+Tab 无图标**
- 根因：`WNDCLASSEXW` 用 `..Default::default()` → `hIcon`/`hIconSm` 恒为 0（脚本实测 `WM_GETICON` 两个句柄都返回 0）。
- 修复：新增 `load_app_icons()`（`LoadImageW` 加载 `IDI_APP_ICON=101`，尺寸取系统指标 `SM_CXICON/SM_CYICON`、`SM_CXSMICON/SM_CYSMICON`，不写死 32/16），填 `hIcon`/`hIconSm`；建窗后再 `SendMessageW(WM_SETICON, ICON_BIG/ICON_SMALL)` 双保险。
- 顺带：`app.ico` 原本只有 32×32 + 64×64，**缺 16×16** → 任务栏小图标靠缩放发虚。已补 16×16 帧（纯 Python 解析 DIB 帧做 2×2 alpha 加权盒式缩放，帧现在是 16/32/64；根目录 `app.ico` 是真源，已同步 crate 副本）。

**② 任务栏单击不最小化/恢复**
- 根因：窗口是 `WS_POPUP`，**没带 `WS_MINIMIZEBOX`/`WS_MAXIMIZEBOX`**。任务栏按钮的"单击最小化"由 explorer 判定窗口是否可最小化后再发 `WM_SYSCOMMAND`——样式位缺失时 explorer 不发这条命令，于是点了没反应。
- ⚠️ 认知纠正（测出来的）：**直接 `SendMessage(WM_SYSCOMMAND, SC_MINIMIZE)` 在无样式位时照样能最小化**（旧 exe 实测 `IsIconic=True`）。所以"DefWindowProc 检查样式位才处理"只对 Wine/部分文档成立，**真机失效点在于 explorer 这一侧不发消息**，别拿"直接发消息能最小化"当"任务栏也能用"的证据。
- 修复：窗口样式 `WS_POPUP | WS_MINIMIZEBOX | WS_MAXIMIZEBOX`（`WS_POPUP` 不画系统标题栏，零视觉回归）。
- **连带必须处理**：补 `WS_MAXIMIZEBOX` 后 `SC_MAXIMIZE` 真正生效，而 frameless 没有系统边框避让任务栏 → 不干预就会**铺满整屏盖住任务栏**。故 `WM_GETMINMAXINFO` 补 `ptMaxSize` / `ptMaxPosition`（钉到工作区）；原先只有 `ptMaxTrackSize`（那是拖拽缩放上限，**不是**最大化几何，两者是两回事）。
- 副作用修复：`WM_NCLBUTTONDBLCLK`（双击标题栏最大化）转发 `SC_MAXIMIZE/SC_RESTORE` 给 `DefWindowProc` 那条路径此前同样失效，一并恢复。

**验证**：`tools/check_window_behavior.py` —— 先拿修复前旧 exe 跑出 FAIL（样式位 False、图标句柄 0x0），确认脚本有效；修复后 PASS（样式位 True、图标句柄非零、最小化→恢复→最大化几何全绿）。门禁 fmt ✓ / clippy exit 0 / test 322 通过。版本 **0.2.3.20261011**。

**⚠️ 待真机确认**：VM 里工作区高 == 屏幕高（1080，RDP 会话无可见任务栏），`ptMaxSize` 的"不盖任务栏"效果在这里观察不到；任务栏单击也需 Z.W. 在有可见任务栏的真机上确认。

## 注册表写不进去的诊断（reg query 找不到键）

用户点"显示经典菜单"后跑 `reg query "...\InprocServer32"` 报"系统找不到指定的注册表项或值"。

`WinRegistry::write_string` 写同一键 → **写成功、读回、reg query（64 位）也确认键落在正确位置**
（`HKCU\Software\Classes\CLSID\{86ca1aa0...}\InprocServer32`，默认空值）。诊断结论：

- **exe 是 x64**（PE machine=0x8664）→ 不是 WoW64 重定向（32 位写会落 `WOW6432Node`）。
- **注册表层完全正确**，问题在 GUI 这次没真正写进去。结合上一轮"点开关后 explorer 重启并开文件夹"
  （`restart_explorer` 只在 slot 0 调用）→ 点击确实命中 slot 0、`set_classic_menu` 执行了，键却没出现。
- 最可能是 **GUI 运行账户与 reg query 所用账户不在同一 HKCU**（网吧批量部署常见：程序以
  其他账户/会话/服务运行，HKCU 被重定向），或用户跑的不是最新 exe。
