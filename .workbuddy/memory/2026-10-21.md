## 附3：pilot3 真机事故修复（Z.W. 截图反馈标题栏消失）

- Z.W. 真机跑预览 exe 后反馈"圆角和自定义标题栏还是没生效"。两张截图定性：
  图1（浅色+系统标题栏）= v1 `zsui-pilot.exe`（未做 frameless，符合预期，
  用户先跑了旧文件）；图2（深空玻璃✅ 但**标题栏整条空白 + 右上灰块**）=
  pilot2 真机事故。md5 确认用户拿到的就是 VM 验证过的同一二进制，
  VM 复现正常（pilot2_repro.png）→ 差异在真机环境。
- **根因**：标题栏 row 用 `text("").flex(1.0)`（空字符串）做弹性占位——
  空文本宽度/行高依赖字体度量，真机字体/DPI 不同时 flex 布局算崩，
  整行被挤坏（灰块=被压变形的 × 按钮）。**修复：`spacer().flex(1.0)`**
  （无字体度量的专用弹性节点）。
- **兜底三连**：× 按钮加 Control 底色（文字失败也有按钮形状）；标题栏底
  1px border 分隔线；根视图显式 theme_mode(Dark) 不跟随系统。
- **圆角兜底**（vendor）：DWM 请求后读回验证，失败 → SetWindowRgn(R=12)。
  环境无关：Win11 真机 DWM 合成（平滑+阴影），Win10/远程/VM 走 region
  （有形状、1-bit 锯齿、无阴影）。region 副作用：阴影消失、resize 不跟随。
- VM 实测 pilot3.png：标题栏全恢复 ✅、四角白=region 裁窗外 ✅、配色全在 ✅。
- **经验**：flex 布局的弹性占位一律用专用 spacer 组件，别用空文本——
  字体度量依赖会让布局在不同环境（字体/DPI）下结果不同。这条对主线
  WinSuiteX 的 GDI 布局同样适用（量高趟/绘制趟必须同一套度量来源）。
- 提交 c6b3108；交付 `zsui-pilot-preview/zsui-pilot3-fixed.exe`（551KB）。
- 待真机复验：× 点击/页签/toggle/滚动 + 环境三问（Win10/Win11、缩放、

- **依据复盘**：B 一路实测暴露的问题层叠——flex 布局环境敏感（空文本弹性
  占位在真机字体/DPI 差异下算崩）、frameless 需三连补丁（style/NCCALCSIZE/
  NCHITTEST）、DWM 圆角在 VM/远程环境不合成（环境硬限制，迁移也解决不了）、
  鼠标交互在 VM 无法验证、DPI 适配踩坑、ghost 标题文字……单个不致命但叠加
  维护成本高；核心收益（渲染质感）对已部署 0.4.8 的维护工具非刚需。
- **清理**：删 `zsui-pilot-preview/`（B 临时预览 exe）；`fluent-preview/`（A）
  暂留等 Z.W. 发落；**分支全部保留作技术档案**（zsui-rdp-probe / zsui-pilot /
  fluent-polish），main（fc3e445）与 dist/ 生产 0.4.8 **零影响**（复验 PASS）。
- **B 的遗产（主线受益，已确认/可选）**：
  ① DPI Aware——主线 app.manifest 已含 PerMonitorV2 ✅ 无需动作；
  ② 圆角抗锯齿——主线 `SetWindowRgn` 窗口圆角是 1-bit 锯齿（Z.W. 最初
  抱怨"窗口圆角模糊"的根源），环境无关的改进 = **HALFTONE 超采样**
  （2-4x 内存 DC 画 + StretchBlt(HALFTONE) 缩回，边缘出灰度过渡）或
  分层窗口（per-pixel alpha，工程量大）——**待 Z.W. 决定是否投入**；
  ③ 布局度量一致性教训——主线"量高/绘制同函数"铁律已覆盖 ✅。
- **重估触发**：zsui 发 1.0/0.3.0 正式版且 Win32 后端稳定后，可重跑
  zsui-rdp-probe（按类名抓窗）再评估；新工具（非重写）可试点。
