## 第三十六轮 · 硬件报告采集/展示问题修复（v0.2.9.20261012）

背景：用户给 `WinSuiteX_硬件报告_2026-10-12-11-14-54.html` + 同刻截图，要求"检查有没有采集和展示问题需要处理"。

审查发现 4 项，处理结论：
- **BUG 1 — 显示器厂商重复「（戴尔）」**：根因 `platform/display.rs` 把 `d.vendor` 存成已本地化的「Dell（戴尔）」，而 `report/lib.rs` 显示器标签构建器又对 `d.vendor` 套 `vendor_zh` 再补括号 → 双重。
  修复（遵循 report/lib.rs:1682「JSON 只存原始英文厂商名」铁律）：`monitor_model_from_device_id` 改为返回**原始 PnP 码**（"DEL"/"SAM"…），采集循环把原始码写入 `d.vendor`，名字仍用 `vendor_display` 嵌入「英文（中文）」；报告标签构建器改走 `brand_display_or`，且当名字已含中文品牌时不再补括号。新增回归测试 `display_vendor_not_duplicated_when_name_has_brand`。
- **BUG 2 — GUI 容量单位 GB/GiB 不一致**：GUI 多处按 1024 进制除（2^30）却标 "GB"（SI 十进制），与报告 "GiB" 口径不符。修复 `gui-gdi/pages.rs`：内存总计/插槽、硬盘、VRAM、导出 `fmt_gb` 全部 "GB"→"GiB"；同步改测试断言 "8 GB 显存"→"8 GiB 显存"。
- **ISSUE 3 — 内存容量口径警告**：报告如实报「OS 32 GiB vs SMBIOS 各槽合计 64 GiB 偏差 102%」，源于固件把一条空 `DIMM 0（CHANNEL B）` 幻影 32GiB 算进 SMBIOS。**判定为预期行为、不修**：警告本身正确，提示用户 SMBIOS 槽位口径不可信；幻影条属固件怪癖，不是采集 bug。
- **ISSUE 4 — GUI 不显示显示器**：by design（显示器仅报告有），不修。

门禁：cargo fmt --check ✅；clippy -D warnings ✅；cargo test --workspace ✅（report 81、含新增回归测试）。
部署：taskkill → cargo build --release --bin winsuitex-gui-gdi → cp dist/ → verify_gui_resource PASS（FileVersion 0.2.9.20261012，图标#101+清单#1 正常）。

- **修复（真正根因，单一数据源）**：给 `vendor_zh.rs::VENDOR_ZH` 补 PnP 码块（英文列与中文列对齐，如 `("DEL","Dell","戴尔")`）。`platform/display.rs` 写原始码、`report/lib.rs` 走 `brand_display_or` 的链路自此全通。
- **回归测试加强**：report 测试加 `assert!(!html.contains("（DEL）"))`；core `pnp_code_resolves_via_core` 加 DEL/SAM/LEN 断言；`unknown_passthrough` 删掉已失效的 LG 两行（LG 现属已知键）。
- **CLI 重建部署**：`cargo build --release --bin winsuitex` → `dist/winsuitex.exe` 由旧 `0.1.0.20261009` 升到 **0.1.0.20261012**（`--version` 确认）。GUI 版 `winsuitex-gui-gdi.exe` 同轮已是 v0.2.9.20261012。
- **真机数据复渲验证**：`./dist/winsuitex.exe --render "dist/客户机/mds/inventory.json" "dist/客户机/mds/inventory_fixed.html"` → `显示器 #1: Dell（戴尔） A221`、`显示器 #2: Dell（戴尔） 42B9`，全容量 GiB/TiB，grep `（DEL）` 计数为 0。证明修复在用户真实采集数据上生效。
