## 第八轮：玻璃主题"降彩 + 提对比"（Z.W. 反馈"颜色搭配有点花眼，字体看不太清"）

### 根因（WCAG 计算 + 截图定位）
1. **花眼** = 硬件页 8 个分组图标用 `C_ACCENT` 8 色高饱和（青/橙/紫/绿/玫红/黄/蓝/粉）。
   C++ 版图标本来就是**单色线性**——Rust 凭空多了一道彩虹，比参照物更花。
2. **看不清** = 白字压在"白 18% 提亮"的玻璃卡上：卡面相对亮度 L≈0.25，
   白字对比度只有 **3.49:1**（WCAG AA 正文要 4.5），字段名 `C_ON_GRAD_FAINT` 更只有 **~2:1**。
   而白字直接压渐变（不提亮）其实有 4.7:1——**问题出在"卡片把底提亮了"，不在渐变太深**。
   菜单页用深色玻璃卡白字一直很清楚，正是同一原理的反证。

### 修法（theme.rs / pages.rs / main.rs）
- 新常量：`C_GLASS_TINT=(20,24,52)` 深 navy（卡片**压暗**而非提亮）、
  `C_ICON=(214,208,248)` 统一淡紫图标描边。
- `accent_of()` 恒返 `C_ICON`（8 色数组保留但弃用）；硬件/磁盘大卡 `fill_glass_round`
  换 `C_GLASS_TINT` 0.22 / 0.30；`card_bg` 增加 `tint` 参数。
- 字段名（kv 键）与菜单页顶部提示行 `C_ON_GRAD_FAINT`→`C_ON_GRAD_DIM`
  （FAINT 直接坐渐变上只有 ~2.7:1，糊）。
- 字号整体 +1：body 13→14 / sub 12→13 / tiny 11→12 / section 14→15。
- 顺手修错别字：磁盘页表头"**族**大小"→"**簇**大小"（详情卡里本来就是"簇"）。

### 验证（新工具 `tools/measure_contrast.py`，PIL + WCAG）
- 硬件页 白字 **6.75:1** / 字段名 **4.94:1**；菜单页 **6.96 / 5.10**；磁盘页 **7.45**（全部 ≥AA）。
- ⚠️ **测量口径**：背景取内容区**众数色**（卡面占大面积）——第一版用"白字最少的行"，
  采到卡片下方裸渐变，数字失真（4.09 是白字 vs 渐变，不是 vs 卡面）。
  磁盘页众数会被薄荷绿选中行 `(216,240,228)` 霸占（全表唯一大面积实色），要先剔除再测。
- 门禁：`fmt` clean / `clippy -D warnings` 0 error / `test` **250 passed**（含 GDI 冒烟 4）。
- 部署 `dist/winsuitex-gui-gdi.exe` = **430,080 B**，`cmp` 验证 dist == build 产物。

### 环境备忘
- 受管 venv 的 python 在 `...envs/default/Scripts/python.exe`（**Windows 是 Scripts 不是 bin**），
  Pillow 12.3.0 已装；gdi_shot/gdi_interact 全靠它。

### 遗留待办
- Rust GUI 版本资源（图标/版权/四段版本号）仍缺；
- 磁盘页"一键复制"按钮未做；

## 第十轮：标题栏两键重构 + 版权居中（Z.W. 反馈"最大化取消，两键功能/hover 有问题，版权没居中"）

### 根因与修法
1. **按钮命中索引反序**（"点左键关窗、点右键最小化 + hover 错位"的根因）：
   绘制端 `closers=[右-3bw, 右-2bw, 右-bw]` 按左→右对应 0/1/2，而 `hit_test` 的
   `i=(right-x)/bw` 从右往左数（最左算 2、最右算 0），与 `on_click` 的
   `0→min,1→max,2→close` 完全相反。修法：`hit_test` 显式映射回**绘制序**
   （`from_right==1 → 0` 最左、`==0 → 1` 最右），绘制/命中/hover 三处同序。
2. **最大化键取消**：`labels/closers` 3→2（`─ 最小化 | ✕ 关闭`），
   `on_click` 删最大化分支（0→SW_MINIMIZE，1→DestroyWindow），
   `nc_hit_test` 按钮区 `bw*3→bw*2`。双击标题栏最大化/还原保留（WM_NCLBUTTONDBLCLK，
   唯还原入口，Z.W. 只说取消按钮）。
3. **版权居中**：`draw.rs` 新增 `text_center`（`DT_CENTER|DT_VCENTER|DT_SINGLELINE`），
   `draw_footer` 版权行改用它。顺手把**两键字形也改居中**（原先 `DT_RIGHT` 让 ✕
   贴到窗口右缘，x 到 594/595）。
4. 产物 **435,200 B**，fmt/clippy/test 全绿（71 tests）。

### 验证方法教训（重要，勿再踩）
- **合成 WM_MOUSEMOVE 验 hover 在新进程上不可靠**：本会话真实光标不在窗内时，
  每次 move 重新注册的 `TrackMouseEvent(TME_LEAVE)` 会被系统立即补发
  `WM_MOUSELEAVE`，把 hover 在 paint 前清零 → 截图永远"没高亮"，但应用逻辑其实是对的。
- 插桩定位法（env 门控 dbg_log 写文件）：在 on_mouse_move / WM_PAINT /
  draw_titlebar 各打一行，立即看出"move 命中 tb=1 → paint 时 hover_tb=-1"。
  **调 render 路径时插桩 > 猜竞态**。
- 最终验证手段：debug 版临时屏蔽 leave 清零（env 门控）→ 抓到
  关闭键 hover 红 `(232,17,35)`、最小化键白叠 `(161,119,242)`，各键正确。
  **插桩与屏蔽已全部移除**，交付代码干净，门禁复跑全绿。
- 点击功能用 `SendMessageW(WM_LBUTTONDOWN/UP)` 直送 wnd_proc 验证：
  点左键 `IsIconic=1`，点右键窗口销毁 ✓（本环境 SetCursorPos/SendInput 均被沙箱禁用）。
- `GetWindowDC+BitBlt` 抓帧走 DWM 重定向表面，窗口被遮挡也能抓；但挪窗到屏外不可靠。
- 注意 `SetWindowPos` 测试挪窗时 flags 必须含 `SWP_NOSIZE(0x1)`，否则窗口被改成 0×0。

## 第十二轮：DPI 感知缺失（Z.W. 反馈"窗口边缘模糊 + 右键增加里的按钮模糊不够细腻"）

### 根因
**全程序没有声明任何 DPI 感知**（无 `SetProcessDpiAwareness*`、无 manifest `dpiAware`）。
非 DPI 感知进程被 Windows 当成 96-DPI，整窗位图由系统 DPI 虚拟化**位图拉伸**到物理像素
→ 边缘/文字/开关全糊。VM 是 96 DPI 看不出（虚拟化只在 >96 DPI 才拉伸），糊的是 Z.W. 真机高分屏。
另一个隐患：`set_dpi(GetDpiForWindow)` 在 `CreateWindowExW` **之后**才调，窗口初始宽高
用 stale 的 96 算——而 `on_paint` 只校正高度不校正宽度，高分屏下窗口会偏窄。

### 修法（main.rs / theme.rs / pages.rs）
1. `main()` 最先声明 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，失败回退
   `SetProcessDpiAwareness(PROCESS_PER_MONITOR_DPI_AWARE)`。⚠️ windows 0.62 里
   `PROCESS_PER_MONITOR_DPI_AWARE` 是 `pub const`（不是枚举变体），直接裸名导入。
2. 创建窗口前 `set_dpi(GetDpiForSystem())`，初始尺寸即真实物理尺寸。
3. 开关细化：滑块加 1px 淡灰描边 `C_SWITCH_KNOB_EDGE=(206,208,226)`；关态轨道加半透明白描边
   （开态 alpha=0 不画）——原生 DPI 下边界清晰。

### 验证
- 门禁：fmt clean / clippy 0 error / **71 passed**；产物 **436,224 B**（+1KB）。
- **运行时硬核验证**：ctypes 调 `GetProcessDpiAwareness(pid)` → **awareness=2
  (PER_MONITOR_DPI_AWARE)**，感知真实生效，不是只编译过。
- 三页 seq 截图无回归（595×950 / 磁盘页 595×416 自适应正常）。
- 96 DPI 的 VM 截图看不出 DPI 修复效果（本来就糊不起来），**真机高分屏复验待 Z.W.**。

## 第十三轮：经典菜单置顶 + 系统判定 + 开关抗锯齿治本（Z.W. 三条反馈）

Z.W.："win11经典菜单项移动到最上面，判断系统是否显示，另外那些开关按钮还是有点糊，不细腻。"

### 1. 经典菜单置顶（pages.rs draw_menu_page）
- 解耦 `slot` 与 `f_idx`：**slot 0 = 经典右键菜单**，`slot 1..=5 = FEATURES`。
- 绘制顺序：页头 → 经典菜单区块（"Windows 11 经典右键菜单"标题 + `feature_row(slot=0, Menu图标)`）→
  "功能增强"标题 → 5 个 FEATURES（slot=i+1）。
- 命中/点击同步重映射：`switch_at` / `toggle_feature` 按 slot 0 = 经典菜单、slot≥1 = FEATURES[i-1]。
  `toggle_feature` 里 `idx==0` 走 `pages::set_classic_menu(!classic_menu_on())`，否则原 install/uninstall 逻辑。

### 2. 系统是否显示（pages.rs is_win11()）
- 读 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\CurrentBuildNumber` ≥ 22000 判 Win11
  （避开 ProductName 误报；与 `winsuitex_platform::system::normalize_os_product` 同口径）。
- 非 Win11（本 VM = Win10 build 19045）：经典菜单开关显示状态 **"仅 Win11"** + 说明
  "当前系统不是 Windows 11（已自带完整右键菜单），此开关无需启用"；状态色用 `C_ON_GRAD_FAINT`。
- 是 Win11：正常"已启用/未启用"，开关可点。

### 3. 开关抗锯齿治本（draw.rs aa_round + pages.rs draw_switch）
- GDI 原生 `RoundRect` 无抗锯齿，高分屏圆角硬锯齿 = "糊"。治本：**超采样 + HALFTONE 平滑缩放**：
  `CreateDIBSection` 建 3× 离屏 DIB → 填 `bg` + `RoundRect`（选 `NULL_PEN` 去黑描边）画 `fg` →
  `SetStretchBltMode(hdc, HALFTONE)` + `StretchBlt` 缩回目标 DC（区域平均 = 抗锯齿圆边）。纯 GDI 无 GDI+。
- `draw_switch` 三层全走 `aa_round`：轨道（bg=卡片色）、rim 淡灰描边环（bg=轨道色）、白色旋钮（bg=描边环色）。
- `theme.rs`：`C_SWITCH_KNOB_EDGE` 加深 `(206,208,226)→(190,193,212)`，让白旋钮边界更清晰。
- ⚠️ **我自查的一项"轨道 Region 裁剪"细化经分析不需要**：`aa_round` 把整块 DIB 先填 `bg`，而三层
  bg 各自等于其下层颜色（轨道bg=卡、rim bg=轨道、旋钮bg=描边环）→ 圆角外方角与下层同色、无缝融合，
  无溢出到卡片的可见问题。加 `CreateRoundRectRgn` 裁剪属过度设计，跳过。

## 第十四轮：开关重设计 + 经典菜单按系统隐藏（Z.W. 三条反馈）

Z.W.："把那开关按钮重新设计，不舒服，另外经典菜单确认只是针对win11系统吧？如果不是win11系统就隐藏吧，多余，还有每点一次开关是必须刷新吗？"

### 1. 开关重设计（pages.rs draw_switch）
- 删掉上轮"淡灰描边环 + 白旋钮"的**双环**（深色卡片上显脏、边界乱）。
- 改为**单色白旋钮 + 下方 1px 软阴影**（`aa_round` 画一颗比旋钮大 1px、下移 1~2px 的暗圆作伪厚度），
  像实体拨钮，观感更安静舒适。轨道/旋钮继续 `aa_round` 抗锯齿。
- 关态轨道 `over(grad, C_WHITE, 0.25)` → `0.30`（更清晰可读的"关"）。
- `theme.rs` 删除已不用的 `C_SWITCH_KNOB_EDGE`（原淡灰描边色）。

### 2. 经典菜单按系统隐藏（pages.rs draw_menu_page）
- 确认：经典菜单是 **Win11 专属**（`CLSID InprocServer32` = Win11"显示更多选项"官方绕过法；
  Win10 默认就是完整菜单，该键无意义）。
- `draw_menu_page` 把"Windows 11 经典右键菜单"区块用 `if win11 {…}` 包起——**非 Win11 整块不绘制**，
  连"仅 Win11"文案都不留（Z.W.："隐藏吧，多余"）。同时清理区块内已死的 `!win11` 分支。
- slot 映射不变（slot 0=经典、1..5=FEATURES）；非 Win11 时 slot 0 不绘制，`switch_at` 不会返回 0，安全。
- smoke test `menu_switch_hit_testing_covers_every_feature` 同步改为：非 Win11 预期命中集合 `{1..5}`、
  Win11 预期 `{0..5}`（之前写死 6 个导致非 Win11 环境假失败）。

### 3. 刷新机制答复（不改行为）
- 每点一次功能开关调用的是 `SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST, None, None)`——
  **轻量外壳通知广播**（告诉资源管理器"关联变了，重读"），**不重启资源管理器**，几乎无感。
- 只有极少数情况右键菜单视觉没更新，才需用户手动重启资源管理器（界面提示那句）。
- 结论：保留该通知（移除反而要用户手动重启），Z.W. 若实测有闪烁再说。

### 验证

### 1. 经典菜单不生效 → 切换后自动重启 explorer

  完全同参（HKCU\...\InprocServer32 默认值=空 REG_SZ），写入本身没问题。
- **修法**（main.rs）：新增 `restart_explorer()`——`GetShellWindow` 定位 shell 进程 →
  `TerminateProcess`；winlogon `AutoRestartShell=1`（系统默认）自动拉起新 explorer；
  600ms 后若 shell 仍缺位再 `ShellExecuteW("explorer.exe")` 显式拉起（幂等双保险，
  若 shell 已恢复则跳过，不会开出重复 shell/文件夹窗口）。`toggle_feature(idx==0)`
  写完注册表即调用。
- ⚠️ VM=Win10 经典菜单块隐藏，重启 explorer 无法端到端验证，**真机 Win11 待 Z.W. 复验**。

### 2. 功能开关"点一下就刷新" → 删除广播（回归 C++ 行为）

  无需通知。Rust 的广播是对 C++ 的有害行为偏离（第十四轮答复"几乎无感"不准确）。
- **修法**：删 `toggle_feature` 的广播；删 `set_classic_menu` 的广播（重启 explorer 已

## 第十九轮：滚到底后分组标题横条底色消失（已修复+VM 验证，待真机复验）
- 现象（Z.W. 真机）：硬件页拉到底后，每个分组标题下的浅色横条（band）底色全没了。
- 根因（GDI 坐标系坑）：`on_paint` 用 `OffsetViewportOrgEx(0,-scroll)` 滚动，`FillRect`
  受视口偏移画到屏幕 `内容y-scroll`；但 `draw.rs fill_glass_round` 里 `CreateRoundRectRgn`
  的坐标是**设备坐标、不随视口偏移移动**，仍停在 `内容y`。两者错位 scroll px：
  band 只有 SEC_H=30 高，scroll≥30 时填充整条落在裁剪区外 → band 背景全没。
  大卡片错位只丢顶/底一截（顶部被固定头部盖住）所以不显——只有小横条中招，
  scroll=0 时两者重合，故顶部正常、滚下去才坏。
- 修法：`fill_glass_round` 建 region 时 `top/bottom` 各减 `scroll`（视口只沿 Y 偏移），
  与填充对齐。头部两处调用 scroll=0 传参，行为不变。
- 验证：临时 WIN_H=360 强制溢出滚动，`tools/r19_shot.py`（修好 wParam 打包的滚轮脚本）
  抓 top/mid/bottom 三态——顶部(系统/主板)、中段(处理器/内存)、底部(硬盘/网卡)
  横条全部可见；还原 948 后三页回归 `tools/r19_final_{hw,menu,disk}.png` 正常。
  门禁全绿（fmt/clippy/259 tests）。
- 工具债已还：`gdi_interact.py` wheel 改为高位直接放有符号格数（原 `notches*120`
