# WinSuiteX 导出报告 · 视觉设计规范（三方向共同输入）

## 1. 产品是什么
WinSuiteX 是一款面向网吧/电竞酒店维护工程师的 Windows 桌面工具（Rust 编写，纯 GDI 自绘玻璃界面）。
它会采集一台计算机的完整硬件与系统信息，并支持**导出为 HTML 报告**便于存档、打印、发给客户。
本规范要定义的就是"导出 HTML 报告"这一产物今后统一的视觉风格——不是一次性美化某一页。

## 2. 目标受众与使用场景
- 受众：维护工程师本人、网吧/电竞酒店老板或客户。
- 场景（用户已确认"两者兼顾"）：
  - 屏幕查看（电脑/手机浏览器打开）；
  - 打印 / 导出 PDF 存档或交付客户。
- 因此：浅色底、对比度充足、灰度打印清晰、不浪费墨；同时头部带品牌渐变。

## 3. 视觉大方向（用户已定）
**浅色正文 + 品牌色头部**。
- 品牌渐变：软件 App 同款 `#8751EE → #2662EB`（即 RGB 135,81,238 → 38,98,235）。
- 底部实色条（App 底栏）：`#1B367A`（可用作页脚或分区点缀，谨慎使用）。
- 正文：白/极浅灰底，干净工具文档气质，像一份"规格说明书"。
- 品牌色只出现在头部与少量强调处，不得整页渐变（避免 AI slop / 打印费墨）。

## 4. 核心信息与内容板块（报告必须覆盖的章节，顺序固定）
1. 操作系统（产品/版本/架构/开机时间/在线时长）
2. 计算机（名称/当前用户/采集时间）
3. 主板 / BIOS（制造商/产品/序列号/BIOS/芯片组）
4. 处理器（型号/规格/代号）
5. 内存（总计/插槽/每条内存详情）
6. 显卡 / 显示器
7. 硬盘（每块盘型号/接口/容量/序列号/固件/健康状态/通电时长）
8. 网卡（型号/状态/速率/MAC/IPv4）
9. 分区与簇大小（10 列表格：盘符/物理磁盘/类型/文件系统/簇大小/总容量/已用/可用/序列号/卷标）
10. 音频设备（带蓝牙/音箱等标签）
11. 键盘 / 鼠标
12. WinSuiteX 功能状态（启用/未启用开关 + 说明）

报告头部：机器名（大字）+ 副标题（如 `WIM-20250421TVP · Rust 版`）。
报告页脚：`WinSuiteX · 重庆持玛多网络科技有限公司 · Z.W.`

## 5. 必须支持的信息元素类型（样式必须覆盖）
- 键值表（左列标签窄、右列值宽）：如"操作系统"各段。
- 宽数据表（10 列，可横向滚动或自适应）：分区表。
- **健康徽标**：良好（绿）、警告（橙/红）——磁盘 SMART 状态。
- **功能状态徽标**：已启用（绿）/ 未启用（灰）——功能状态段。
- **标签 chip**：蓝牙、音箱、耳机等——音频设备。
- **厂商中英文括注**：`ASUS（华硕）`、`Intel（英特尔）`，英文优先、中文括注。
- **等宽串**：序列号、MAC、UUID、路径、固件号——用 Consolas/Menlo 等宽字体，允许断词换行。
- **警告框**：SMART 异常等提示性内容（现有 `.warnbox`）。
- **缩写/百分比**：如"82%（已用）"。

## 6. 情感基调与气质关键词
专业、可靠、克制、有品牌感、像"工程师的规格说明书"。不花哨、不拟物、不卡通。

## 7. 输出格式与尺寸（三方向必须统一）
- **单文件自包含 HTML**：不引用任何外部 CSS / 字体 / 图片 / 网络资源（导出后离线双击即开）。
- 页面主体最大宽度约 **900–960px**，居中。
- 字体：系统字体栈（`"Microsoft YaHei","PingFang SC","Segoe UI",system-ui,sans-serif`）+ 等宽栈（Consolas/Menlo/monospace）。**禁止加载外部字体**。
- 必须含 `@media print` 规则：隐藏不必要的阴影/背景、保留 header 渐变或改为实色、A4 友好、避免章节在页尾断裂（`break-inside: avoid`）。
- 正文 ≥14px，标签/注释 ≥12px，正文对比度 ≥4.5:1。

## 8. 已知约束（红线，任何方向都不得违反）
- ❌ 禁止 emoji 作图标（用 CSS/SVG 简笔线条或纯文字标签）。
- ❌ 禁止整页紫渐变、禁止每个标题都配图标、禁止圆角卡片+左彩条这套 slop 组合（除非品牌 spec 明确保留）。
- ❌ 禁止 Inter/Roboto 等需联网字体；用系统字体。
- ✅ 品牌渐变只用于头部（及可选的极少量强调）。
- ✅ 中文引号用「」而非 ""。
- ✅ 真实内容优先：用样例里的真实数据，不得编造 stats。

## 9. 图片需求（Phase 3.5 判定）
**不需要图片**。这是数据/工具型报告，无内容必需的照片或产品图。
Logo：可用品牌渐变 + 文字 wordmark「WinSuiteX」表达，不强制嵌入图标文件（保持单文件自包含、零外部依赖）。若某方向想加一个简单 SVG 标记，须内联、纯矢量、不依赖外部资源。

## 10. 视觉母题假设（从内容长出来的特色，三方向各自诠释）
- 母题线索：这是"一台机器的体检单 / 规格档案"。
- 可衍生的视觉母题：① 规格编号（01–12 章节号，像产品 datasheet）；② 状态色系统（绿/橙/红 健康语义贯穿全篇）；③ 等宽"机器语言"串（序列号/MAC）作为质感细节。
- 三个方向应围绕上述母题之一做差异化诠释，避免趋同。

## 11. 三方向各自的差异化要求（详见各 subagent 指令）
- 方向 A（瑞士网格/国际主义）：章节号 + 发丝分隔线 + 品牌色仅头部与强调线，强排版网格感，最像"技术规格书"。
- 方向 B（现代仪表板卡片流）：头部渐变 + 机器名 + 顶部关键 chips（OS/CPU/RAM 摘要），正文用白卡 + 极轻阴影（无左彩条），屏幕感更强。
- 方向 C（品牌画册/编辑式）：更大胆的头部渐变 bleed + 大号 wordmark，章节用细线分隔 + 内联简笔 SVG 图标（线条、非 emoji），编辑节奏感，最"有设计"。

三版**布局骨架必须互异**，且都用同一份真实内容（见 `../dist/WinSuiteX_硬件报告_2026-10-10-11-17-46.html`），只换设计逻辑，方便横向对比。
